# Audit 2026-11-18, round 24 (Save As, D-108, round 1)

The first audit of Save As in the Downloads pane (D-108), at commit 48a1e74. Two independent auditors read the change
(`bad7471..48a1e74`): A the Instagram side, B videos, galleries, Download All As… and the tests. B ran the real bridge's
`item_key` and `item_meta` with the bundled Python and read gallery-dl's extractors. Every finding was checked against
the code before it was closed.

## Why the rules changed

Ten majors, and nine of them had one cause: Save As wrote into the memory Automatic downloads read (account folder
records, the download archive, saved-posts memory), and also read other folders' memory. Patching each case (marking
records, excluding them from searches) had already started to grow, so D-108 was rewritten with simpler rules before any
fix: Save As makes and changes no memory (except the record of exactly the chosen folder when MediaPull already remembers
it as that account's), judges what the folder holds from the folder alone, puts everything that is not the account's own
media straight into the chosen folder, and looks for copies in the whole chosen folder. The record marking added in
48a1e74 was reverted.

## Tests that could pass while the feature was wrong (B)

Closed: gallery fixtures now use the metadata the app writes and a post numbered from 0; videos cover a folder holding
everything; Download All As… covers gallery and video entries; the stand-in bridge reads the tray and saved posts against
their own lists as the real bridge does; the self-test checks that Save As made no records and that Automatic still goes
to the account's own folder.

## Unproven (carried)

- A Plain-layout video that needs conversion may not re-encode byte for byte, so a Save As could keep a second copy.
- Two records of one folder spelled NFC and NFD (no longer relevant to Save As, which makes none).
- `FollowedFolder.now()` prefers whatever folder is at the old path, so a Retry after the chosen folder was trashed and a
  new one made at its path goes into the new one.
- `entryFolder` could take a child "Saved posts" or "Hashtags" folder that one account dominates.

## Checked and fine (A and B)

Exact account pulls stay in the chosen folder (posts, reels, stories, highlights, Account details, tagged, reposts); the
D-88 owner check; runPull follows the chosen folder and never falls back to a record's folder; Retry and Resume keep
`exact`; continuations and Update of a remembered folder; video and gallery targets, side files beside videos, Retry
following renames, per-job keys; entry names with "..", "/", empty, reserved names and Unicode stay inside; Automatic code
paths for videos, galleries and Download All are unchanged; no crash on ordinary input; no egress change.
