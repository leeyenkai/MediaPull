# Audit 2026-11-21, round 3: metadata edits and Edit/Frame

Same scope and auditors' split as rounds 1 and 2 ([2026-11-21-1.md](2026-11-21-1.md), [2026-11-21-2.md](2026-11-21-2.md)).
Fresh auditors first verified round 2's fixes. Totals: 1 critical, 9 majors, 19 minors.

Five of the photo majors came from one cause, the recipe store keeping one recipe per path while D-127 keeps recipes of
files that are not the one now at that path. The answer is a simpler rule written into D-127 rather than a patch per
case: recipes are kept by their own id, a file is shown the newest recipe made for it, and Revert removes only that one.

## Minors

Fixed: A3-3 (a file followed as it is replaced refreshes nothing; the batch's last call refreshes listings and people
once), A3-4 (the photo's XMP copies of its dates stay in XMP form with their zone and fraction of a second), A3-5 (one
rule: a locked photo is refused, also where its values would go to a `.xmp`), A3-6 (a step is dropped when its rename
fails, so History never lists a change not made), A3-7 (members of a unit written in place are judged one by one; a unit
counts as one photo in History), A3-8 (people count only faces of content some file holds), A3-9 (a swap left at launch is
settled and the edit kept, not the whole batch taken back; R-4503 amended); B3-m1 (the canvas renders in Display P3, so
wide colours an export keeps are not clipped), B3-m2 (a font download that finishes later changes only the family of the
layer as it is then), B3-m3 (a batch's ⌘Z is registered only while the section is shown), B3-m4 (Paste Settings skips
audio, to which none of the settings apply); C3-3 (AIFF keeps artwork; artwork and album artist are hidden for WAV, which
cannot hold them), C3-4 (a video or audio export whose metadata file could not be written says so), C3-5 (a video
export's metadata file takes its new size and loses the place when the location is left out), C3-6 (an MP4 keeps its
capture date and a location in user data), C3-7 (32-bit and 64-bit float PCM keep their depth: encoders added to the
build), C3-8 (a size setting that would not shrink the picture keeps an export lossless), C3-9 (the licence notes say
LAME's export list is changed and take its version from the build), C3-10 (the player reaches the whole file: as C3-2).
Also: font downloads run off the main actor (`@concurrent`).

## Checked and fine (from the reports)

Round 2's fixes verified: Frame-tab bindings, moves taking the new creation date (measured: APFS to exFAT gives a new
one), no pruning at launch, Remove Location removing the position only, locked files refused on Undo and Redo, date
shifts keeping a blank date, facts read off the main actor, `.xmp` values laid over exports, Look and Adjustments pasted
apart, the export folder following moves. The first-dot name index covers every name units, metadata files and `.xmp`
files use; record throttling, per-file follow ordering, edit counts, Undo/Redo of made and cleared `.xmp` files and swap
settling at each crash point are correct; on an iPhone HDR JPEG, a 35 mm scan and a Samsung HEIC the in-place copy keeps
every tag, the gain map and the EXIF thumbnail. Exports are staged and never overwrite; preview and export share the
renderer; geometry composes correctly; references on exFAT resolve to nothing rather than to a wrong file. Video and audio:
the measured length was never zero or short on 14 kinds of file (chained Ogg and joined MP3s included); 308 audio exports
(11 sources to 7 outputs, cut, fade, tags and whole file) cut on the expected samples or within one frame for copies, with
fades, loudness, tags, artwork, depth, rate and channels right; the video location filter, lengths after cuts, fades and
speed, Export Selected, and every codec, filter and muxer the code uses are in the build with matching pins.
