# Audit 2026-11-18, round 15

Round 14 was closed in commit d1951f1. Three independent auditors read the code. A ran the real bridge against the
bundled yt-dlp with a made-up site (no network), B drove the journal on a scratch disk image and NSUndoManager in an
AppKit harness, and C checked D-98's premise against 1.7's code (it holds: 1.7 knew an item only while its file existed).
Findings two auditors made are listed once, with both ids. Every finding was checked against the code before it was
fixed.

## What changed in approach

Playlist Retry had a major in each of rounds 11 to 15, each from a rule about yt-dlp's limit that its tests checked only
at the level of a function. This round settles the rule (D-99: "At most" counts the job's saves, Retry included) and adds
`Engines/bridge/test_stream_runs.py`, which runs downloads through the real bridge and the bundled yt-dlp with a made-up
site, offline, so a filter or limit that works alone but not inside yt-dlp fails the check. It runs in `check.sh`.

## Findings

### Major

| # | Finding | Closed by |
|---|---|---|
| A15-M1 | Retry by id downloaded nothing: the filter rejected the playlist itself (and entries whose id was not known yet) | Only a video is asked for by id; the playlist and unknown entries pass and are checked once known. `test_a_retry_downloads_the_failed_videos` (real yt-dlp run) |
| A15-M2, C15-M3 | A video that failed in saving was left out of Retry by id | It is retried by its id like a download failure |

| A15-M4 | A single video was not saved when a subtitle failed | yt-dlp's errors never stop a download; the subtitle is a note. `test_a_subtitle_that_fails_never_stops_the_video` |
| B15-M1, C15-M2 | B14-M2's job had no task: Quit did not wait, Cancel did nothing, and a quit left the journal wrong | Undo and Redo stop between items when cancelled and save as they go; the job holds the task and runs. `testAnUndoStoppedPartWayIsRecorded`; Quit itself is Person |
| C15-M1 | D-98's promise was not built: a 1.7 folder never remembered the files it held, so one deleted after the first 1.8 Update came back | Every pull or Update that reads a folder remembers what it holds. `--selftest-update` "a file held before the first Update and deleted since stayed deleted" |
