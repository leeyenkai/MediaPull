# Audit 2026-11-18, round 25 (Save As, D-108, round 2)

The second audit of Save As, at commit cb8776c, after D-108 was rewritten in round 24. Two independent auditors: A the
Instagram side and its interaction with Automatic downloads, B videos, galleries, Download All As… and the tests. A ran
the real bridge's `KnownTracker` with the bundled Python; B ran `item_key` and `item_meta` and read gallery-dl 1.32.19 and
yt-dlp 2026.10.26 from the pinned wheels. Every finding was checked against the code before it was closed. The fixes are
small and local: no rule of D-108 changed, its wording was made exact in three places.

## Findings

### Major

| # | Finding | Closed by |
|---|---|---|
| A25-M1 | Resume of an account Save As read the folder again, so what the job had saved counted as held and ended the walk early (Reels, stories, highlights) | What a folder MediaPull does not remember held when the job began is read once per job. `--selftest-save-as`: 14 Reels held by a check after 13, then resumed, reach all 14 (13 without the fix) |
| A25-M2 | Renaming or trashing a Save As folder MediaPull does not remember, while the job ran, made it again at its old path | Its files never make the folder again (`accountFolderExisted`), and account documents are not written to a folder that is gone |
| A25-M3 | A Save As of an account rewrote the account's remembered choices, which Update, Update All and Download All use | Not written in Save As (D-108 rule 5) |
| A25-M4 | Download All As… put a hashtag into the account folder of the same name, and the reverse | Hashtag entries are named `#tag`; an account's entry takes a folder of its name only when it holds nothing or the account's own media; anything else never takes an account's folder. `testDownloadAllEntriesStayInsideTheChosenFolder` |
| B25-M1 | On sites that number files without a count, the metadata file has no number, so a held later file counted as holding the post's file numbered 0 (pixivFANBOX covers) | A metadata file without a number is never taken as held; such files are downloaded again and dropped as copies (D-108 rule 3). `testKeysComeFromTheFoldersOwnMetadataOnly` |

## Unproven (carried)

- A Plain-layout or converted file may not re-encode byte for byte, so dropping a re-download as a copy could miss it.
- `exactPlace` matches a remembered folder by its current path; a record whose path is stale treats it as not remembered.
- D-78 recognises an account folder by what it holds, so a Save As copy made before any Automatic download can later be
  taken by Automatic as the account's folder (A, raised as a question for the spec, not a code defect).
- Automatic account Resume may share A25-M1's pattern (outside this audit's scope; recorded for the next 1.8 audit).
- `"<name> (<site>)"` folder names are cut at 120 bytes, so a very long site name can lose its suffix.

## Checked and fine (A and B)

The chosen folder is followed between runs and never falls back to a record's folder; saved-posts and owners memory are
neither read nor written; every archive write is guarded; per-owner routing is skipped; the remembered-folder exception
keeps D-88, places and the early stop as an Update; videos and gallery files go straight in or into their entry folder;
side files stay beside their video; Retry keeps `exact` and `perSource`; entry names with "/", "..", reserved names,
Unicode and empty names stay inside; a file at an entry's name gets a numbered folder; no egress change.
