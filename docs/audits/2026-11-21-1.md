# Audit 2026-11-21, round 1: metadata edits and Edit/Frame

Scope: the features decided after the 1.8 audit, D-119 to D-131, chiefly photo metadata edits (section 45) and
Edit/Frame (section 46) for photos, videos and audio, with the ffmpeg build. Three independent auditors (A: metadata
edits; B: Edit/Frame for photos; C: video, audio and the build) worked under [AUDIT.md](../AUDIT.md), proving each
finding with the code and a failing case; several were measured with generated files and the built ffmpeg.

Totals: 1 critical, 10 majors, 52 minors. Every critical and major is fixed with a test; the minors are fixed unless
noted.

## Critical

| ID | Finding | Fix | Proved by |

| B1-1 | Opening an SVG or stream address in Edit/Frame crashed (`tabs[0]` of none) | Only photos, videos and audio open (`EditModel.editable`); `tabs.first` | `--selftest-edit-photo` paths; code |

## Checked and fine (from the three reports)

The original is only read by Edit/Frame; exports and metadata edits never write over another file; pictures are proven
the same before a file is replaced (pixels, auxiliary images, maker notes); swaps are recorded before anything moves on
exFAT; analysis is rekeyed with people and corrections; recipes stay in Application Support; Core Image and Core Text
only in MediaPullEdit; font downloads only after the opt-in; cancelling exports stops them and leaves no partial file;
unusual paths (quotes, Unicode, leading dashes) in ffmpeg arguments; every codec, muxer and filter the code asks for is
in the build; LAME pinned by SHA-256 with its licence shipped.
