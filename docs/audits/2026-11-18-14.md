# Audit 2026-11-18, round 14

Round 13 was closed in commit 4cdb02a. Three independent auditors read the code. A ran the real bridge against the
bundled yt-dlp with a fake extractor (no network), B drove the journal on a scratch disk image, and C disassembled the
bundled yt-dlp. Findings two auditors made are listed once, with both ids. Every finding was checked against the code
before it was fixed.

## What changed in approach

Five of round 14's majors (A14-M2, A14-M3, A14-M4, B14-M3, C14-M1) were about what earlier versions remembered of
deleted items. Rounds 3, 10, 11, 12 and 13 each patched that with a new rule: dates, an "only folder" rule, records made
at launch, paths kept through renames. Each rule opened new cases. Reading 1.7 settled it: 1.7 knew an item only while
its file was there (`knownKeys` filtered on `fileExists`), so 1.7 itself downloaded a deleted item again. There was no
memory of deleted items to carry over. D-98 removes the takeover: a 1.7 folder starts from the files it holds, exactly
as 1.7 behaved, and 1.8 remembers deletions from its first pull on. Where a 1.7 pull stopped is still continued.
